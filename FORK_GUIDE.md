# Що таке Fork і коли його використовувати

## Що таке Fork?

**Fork (форк)** - це копія репозиторію GitHub, яка створюється у вашому власному обліковому записі GitHub. Це дозволяє вам вільно експериментувати зі змінами без впливу на оригінальний проект.

## Різниця між Fork і Clone

### Fork
- Створює копію репозиторію **на GitHub** у вашому обліковому записі
- Зберігає зв'язок з оригінальним репозиторієм
- Дозволяє відправляти Pull Request до оригінального проекту
- Використовується для внеску в чужі проекти

### Clone
- Завантажує копію репозиторію **на ваш локальний комп'ютер**
- Не створює нову копію на GitHub
- Використовується для локальної роботи з кодом

## Коли потрібно робити Fork?

### Використовуйте Fork, якщо:

1. **Ви хочете внести зміни в чужий проект**
   - Ви не маєте прав на запис до оригінального репозиторію
   - Ви плануєте відправити Pull Request з вашими змінами

2. **Ви хочете створити свій власний проект на основі іншого**
   - Ви берете існуючий проект як відправну точку
   - Ви плануєте розвивати проект у своєму напрямку
   - Ви хочете зберегти зв'язок з оригіналом для отримання оновлень

3. **Ви хочете експериментувати без ризику**
   - Тестування нових функцій
   - Вивчення коду через модифікацію

### НЕ використовуйте Fork, якщо:

1. **Ви працюєте над своїм власним проектом**
   - Просто створіть новий репозиторій

2. **Ви член команди з правами доступу**
   - Використовуйте гілки (branches) замість форку

3. **Ви просто хочете завантажити код локально**
   - Використовуйте `git clone`

## Як створити Fork?

### Через веб-інтерфейс GitHub:

1. Відкрийте репозиторій, який хочете форкнути
2. Натисніть кнопку **"Fork"** у верхньому правому куті
3. Виберіть ваш обліковий запис як місце призначення
4. Дочекайтеся створення форку

### Після створення форку:

```bash
# 1. Клонуйте ваш форк на локальний комп'ютер
git clone https://github.com/YOUR_USERNAME/REPOSITORY_NAME.git

# 2. Перейдіть у директорію проекту
cd REPOSITORY_NAME

# 3. Додайте оригінальний репозиторій як upstream (необов'язково, але рекомендується)
git remote add upstream https://github.com/ORIGINAL_OWNER/REPOSITORY_NAME.git

# 4. Перевірте налаштовані віддалені репозиторії
git remote -v
```

## Робота з Fork

### Синхронізація з оригінальним репозиторієм:

```bash
# 1. Отримайте зміни з оригінального репозиторію
git fetch upstream

# 2. Перейдіть на вашу основну гілку
git checkout main
# або
git checkout master

# 3. Злийте зміни з upstream
git merge upstream/main
# або
git merge upstream/master

# 4. Відправте оновлення у ваш форк
git push origin main
```

### Створення Pull Request:

1. Внесіть зміни у вашому форку
2. Відправте зміни на GitHub: `git push origin your-branch`
3. Перейдіть на сторінку вашого форку на GitHub
4. Натисніть кнопку **"New Pull Request"**
5. Виберіть гілки для порівняння
6. Додайте опис змін
7. Натисніть **"Create Pull Request"**

## Альтернативи Fork

### Створення нового репозиторію з існуючого коду:

Якщо вам НЕ потрібен зв'язок з оригінальним проектом:

```bash
# 1. Створіть новий репозиторій на GitHub (без README)

# 2. Клонуйте існуючий проект
git clone https://github.com/ORIGINAL_OWNER/REPOSITORY_NAME.git my-new-project

# 3. Перейдіть у директорію
cd my-new-project

# 4. Видаліть старий git remote
git remote remove origin

# 5. Додайте новий репозиторій як origin
git remote add origin https://github.com/YOUR_USERNAME/NEW_REPOSITORY_NAME.git

# 6. Відправте код у новий репозиторій
git push -u origin main
```

### Використання Template Repository:

GitHub дозволяє створювати репозиторії-шаблони, які можна використовувати для створення нових проектів:

1. Власник оригінального репозиторію може позначити його як Template
2. Ви натискаєте **"Use this template"** замість Fork
3. Створюється новий незалежний репозиторій без історії комітів

## Висновок

**Використовуйте Fork коли:**
- Ви хочете внести вклад у чужий проект
- Ви хочете зберегти зв'язок з оригінальним проектом

**Створюйте новий репозиторій коли:**
- Ви хочете повністю незалежний проект
- Вам не потрібна історія оригінального репозиторію
- Вам не потрібно синхронізуватися з оригіналом
